Design DNA · Contributor guide

把一张卡片，做成可复用的设计 DNA。

这份指南是一套实战 SOP，告诉你如何把一张静态/原创卡片升级成可下载、可复用、可被 AI 理解的设计系统素材包。它由 a.Record 这张样本卡走通后提炼，跟着做，结果会和它一样兑现。

01哪些卡片值得做 kit

不是每张卡片都该做。判断标准只有一条：这张卡片的视觉语言是不是属于「我们」。

✅ 做 kit

  • 原创卡片：在 variant-clone/ 内部从零写的，token 全在我们手里
  • 静态截图卡片：把外部页面的精神浓缩成 1100×720 静态构图（如 Marginalia 静态预览），视觉决策由我们做
  • 已经具备完整视觉系统：有清晰的色彩 / 字体 / 圆角 / 间距规则，能被抽象出来

❌ 不做 kit

  • 外站镜像类：Nathan Smith / Lorenzo / SuperHi / WebGL Magazine / Skeleton Fluid 等通过 <base href> 镜像原站的卡片，token 不属于我们
  • 构建产物类：Three.js / WebGL bundle 卡片（Delphi / GPU IO / Cinematic Scroll），核心在压缩 chunk 里，无法干净抽 token
  • 实验/未确认：还在迭代视觉、可能下架的卡片
!

不做 kit 的卡片仍可正常出现在灵感库，只是 hover「提取 DNA」时会 flash 提示「该卡片暂未提供 DNA」，不影响其它体验。

02两种规格

根据产能选一种。Minimum 是基础合规，Perfect Sample 才是我们追求的样本品质。

Tier 1 · minimum

最小合规 kit

能让 hover「提取 DNA」按钮可点击、能下载到一份能用的 zip。当卡片视觉成型但还没有铺成 flagship 的精力时使用。4 个文件。

  • design-system.css
  • design-system.md
  • design-tokens.json
  • README.md
Tier 2 · flagship · 推荐

完美样本 kit

真正实现「下载即开发，AI 立刻懂」的兑现。把 token 做穿、组件拆出、衍生用例验证、AI 提示词配齐。17 个文件。a.Record 是它的参考实现。

  • README.md · design-system.md
  • design-system.css · design-tokens.json
  • ai-prompt.md · tailwind-tokens.js
  • index.html（可视化文档页）
  • components/01-08（8 个组件）
  • examples/original.html
  • examples/<second-use-case>.html

03抽 token（流程第一步）

从卡片源 HTML 把视觉语言抽象成可复用 token。这一步决定了整个 kit 的天花板。

读源文件

打开 variant-clone/<card>.html。重点看 :root、html, body、关键 panel 类。把 hex 颜色、字体栈、字号、圆角、阴影、动效 cubic-bezier 全部抓出来。

命名空间前缀

每张卡片用一个 2–3 字母前缀，避免多 kit 同时引入时 :root 变量打架。

  • --ar-* = a.Record
  • --cr-* = Carrot
  • --mg-* = Marginalia
  • 新卡按缩写自取 → 不冲突即可

token 应该至少分这 6 类

  1. Color：surface scale（4–6 阶）+ ink ramp（3–4 阶）+ 至多一个 accent
  2. Typography：sans + mono 双家族 / 字号阶梯（10 步以内）/ letter-spacing 预设
  3. Spacing：4px grid（sp1=4 → sp8=32）
  4. Radius：5 步阶梯（shell > panel > card > tile > pill=999）
  5. Shadow：3 类（card / glass / pill），不要更多
  6. Motion：2 个 ease + 3 个 duration（fast/base/slow）
陷阱 · Token 通货膨胀

不要把源 HTML 里所有 hex 都搬过来。如果你抽出超过 12 个色 token、6 个圆角、5 个阴影，说明源卡本身没有"系统"——先回去清理源卡，再做 kit。

04写 4 份核心文档（Tier 1 必含）

这 4 个文件是 kit 的最小集，缺一不可。

kits/<slug>/design-system.css
/* 顶部用 @import 加载字体 */
@import url('https://fonts.googleapis.com/css2?family=Inter:wght@300;400;500;600&display=swap');

:root{
  /* 1. Typography */
  --ar-font-sans: 'Inter', sans-serif;
  --ar-font-mono: 'Geist Mono', monospace;
  --ar-fs-h1:    34px;
  --ar-fs-base:  13.5px;
  /* 2. Color */
  --ar-c-bg:    #eceae3;
  --ar-c-shell: #ffffff;
  --ar-c-ink:   #1c1c1a;
  --ar-c-rec:   #f24a3a;  /* 唯一 accent */
  /* 3-6. Spacing / Radius / Shadow / Motion 略 */
}

/* 紧接着写 utility classes，最少 5 个 */
.ar-shell{ background: var(--ar-c-shell); border-radius: 30px; padding: 28px; }
.ar-pill { height: 34px; padding: 0 14px; border-radius: 999px; ... }
kits/<slug>/design-tokens.json
// W3C Design Tokens 草案格式：每个值用 $value/$type 包裹
{
  "name": "a.Record Design System",
  "version": "1.0.0",
  "color": {
    "bg":   { "$value": "#eceae3", "$type": "color" },
    "rec":  { "$value": "#f24a3a", "$type": "color",
              "$description": "Only for live/error/destructive" }
  }
}

验证：python3 -c "import json; json.load(open('design-tokens.json'))"

design-system.md 必含 9 节

  1. Personality（个性 + 参考品牌）
  2. Color（色彩 + 用法说明）
  3. Typography（字体阶梯 + 数字必须 mono）
  4. Spacing & Layout
  5. Elevation（3 类阴影）
  6. Motion
  7. Components 表（class → 描述）
  8. Do / Don't
  9. Extending（如何安全扩展）

README.md 必含

  • What's inside（文件树）
  • Quick start（4 种用法：直接看 / link CSS / Tailwind preset / AI prompt）
  • Design intent（一句话定调）
  • Credits & license

05拆 8 个独立组件（Tier 2）

每个组件是一个独立可运行的 1100×600 HTML，带 <link rel="stylesheet" href="../design-system.css">。打开能跑，看源能拷。

挑组件的标准

  • 这一类元素在卡片里出现至少 2 次（不是孤本）
  • 能用 token 拼出，不依赖魔法值
  • 有清晰的"独立感"——单看也是个组件，不是某个布局碎片

a.Record 的 8 个示例

  1. 01-shell — 外壳容器
  2. 02-pill — 胶囊按钮（含 default / icon / dark / red 4 变体）
  3. 03-glass-panel — 毛玻璃浮层
  4. 04-status-dot — 状态指示（含 idle / live 两态）
  5. 05-mono-display — 等宽数字（计时 / 电平 / 容量）
  6. 06-meter-ring — 仪表圆环（带真实低通平滑动画）
  7. 07-spectrum-bars — 频谱柱
  8. 08-cap-label — 大写小标签 + section heading

不一定非得是 8 个，关键是覆盖原卡的所有原子级元素。少于 5 个说明卡片的"零件"不够；多于 12 个说明颗粒度太细。

06写衍生用例（系统跨用例的检验）

这一步是整个 kit 最重要的检验。如果 token 只能撑起原卡片，那它就不是 design system，只是 CSS 备份。

规则

  1. examples/original.html — 复制原卡 HTML 作为参考
  2. examples/<second>.html — 必须是完全不同的用户场景，不能换汤不换药

第二个用例怎么选

  • 原卡是 dashboard → 第二个做 settings page / pricing
  • 原卡是 hero/landing → 第二个做 inbox / list view
  • 原卡是 editor → 第二个做 onboarding / 对话框

a.Record 是录音 dashboard，第二个用例选了「账户设置」页（profile + studio defaults + pricing tiers + danger zone）。如果它仍然像 a.Record，token 系统就成立。这是不可妥协的检验。

陷阱 · 假衍生

不要把第二个用例做成「原卡换文案」。如果两个 example 视觉上 80% 重合，说明 token 还没有被"逼出来"——回去拆 token。

07AI 接入产物（让 AI 能用这套系统）

设计系统真正的杠杆是被 AI 工具消费。配齐两个产物，让用户能在 Cursor / Claude / WorkBuddy 里直接调用风格。

ai-prompt.md（必含 4 段）

  1. Cursor / Claude rule：60–120 字的 system prompt，列禁止项 + 必含项
  2. Generation prompt template：包装用户请求的 wrapper（"用 a.Record 风格做…"）
  3. Do / Don't：硬禁止条款
  4. AI-readable JSON：MCP / function-calling 工具消费

tailwind-tokens.js

CommonJS 导出 Tailwind preset，让用户 presets: [require('./tailwind-tokens.js')] 即可拿到所有命名空间。映射规则：

  • color → bg-canvas / text-ink / text-rec
  • radius → rounded-shell / rounded-panel / rounded-card
  • shadow → shadow-card / shadow-glass / shadow-pill
  • font → font-mono 自动指向 Geist Mono

验证：unset NODE_OPTIONS && node -e "require('./tailwind-tokens.js')"

08可视化文档页 index.html

这是用户进 kit 后看到的第一个页面，也是「下载完整素材包」「去 WorkBuddy 开发」两个按钮的入口。

结构

  • 左侧 sidebar（268px）：4 段导航 — 基础 / 组件 / 示例页面 / AI 接入；底部两个胶囊：下载完整素材包（黑） + 去 WorkBuddy 开发（白描边）
  • 右侧主区：Foundations 4 节（色彩 swatches / typography rows / spacing & radius scales / motion 代码块）+ Components 8 个 iframe 预览 + Examples 2 个 iframe + AI 提示词复制块 + Tailwind 用法块

核心交互

  • 滚动 → sidebar active link 自动跟随
  • 「下载完整素材包」按钮 → JSZip 懒加载 → 浏览器内打包 17 个文件 → 触发下载
  • 「去 WorkBuddy 开发」按钮 → 复制 prompt 到剪贴板 → iframe 触发 codebuddy://codebuddy-ide deep link 唤起桌面应用 → 1.2s 兜底跳官网

视觉风格直接用本卡片的 design-system.css，相当于"用我们自己的 token 做出我们自己的文档"——这也是检验。

2

worktree + git archive 把 main HEAD 已跟踪文件刷到发布分支。

11Do / Don't

✅ Do

  • Token 用唯一 2–3 字母前缀
  • 必须保留唯一 accent 颜色（哪怕换色，也只能一个）
  • 数字一律 mono + tabular-nums
  • 第二个 example 用完全不同的用户场景
  • 本地起 HTTP 服务跑全流程验证
  • 显式 git add，不要 git add .
  • 下载 zip 后双击 index.html 必须仍可运行

❌ Don't

  • 不要给镜像类卡片做 kit
  • 不要超过 12 个色 token、6 个 radius
  • 不要引入第二个高饱和 accent
  • 不要让两个 example 视觉重叠
  • 不要在 srcdoc iframe 里用相对图片路径
  • 不要直接复制英文模板，所有用户面向文案中文化
  • 不要在 about:blank 上下文使用相对 URL（必须 new URL(rel, location.href).href）

12常见坑

1. git add . 把 artist-month 实验文件带上

这些文件是历史遗留实验，已经判定不收录。永远显式 git add kits/<slug>/ index.html，或在 commit 前 git restore --staged。

2. file:// 下 fetch 被 CORS block

kit 的「下载素材包」按钮在 file:// 协议下 fetch 失败。本地一定用 python3 -m http.server 起服务测，或直接用线上 GitHub Pages URL。

3. iframe srcdoc 中相对路径解析失败

缩略图卡片如果用 src="./foo.png"，在 srcdoc 沙箱里会失败。必须用绝对线上 URL：https://karosu3510.github.io/design-dna/foo.png。

4. about:blank 占位窗口的相对 URL 解析

「提取 DNA」按钮 window.open('about:blank') 后，win.location.href = './kits/...' 会基于 about:blank 解析 → 空白页。必须 new URL('./kits/' + slug + '/index.html', location.href).href。

5. GitHub Pages 部署延迟

push 完 25–60 秒才生效。curl -sI 第一行经常是 tunnel 的 200 Connection established，真正的 HTTP/2 200 在下一行。用 grep '^HTTP/' | tail -1 取最后一行。

6. NODE_OPTIONS 阻止 node 校验

项目内置 node 带 --use-system-ca，导致 node -e ... 报 not allowed in NODE_OPTIONS。校验 tailwind preset 前 unset NODE_OPTIONS。

13完成判定 · 12 项

全部勾上才算"做穿"。Tier 1 只需 1–4，Tier 2（flagship）必须 12 项全勾。

  • 1. kits/<slug>/design-system.css 用唯一前缀，至少 5 个 utility class例如 .ar-shell / .ar-pill / .ar-glass / .ar-mono / .ar-cap
  • 2. design-tokens.json 通过 json.load 校验
  • 3. design-system.md 含 9 节（personality + 6 类 token + components 表 + do/don't + extending）
  • 4. README.md 含 4 种 quick start 方式 + credits
  • 5. components/ 至少 5 个独立 HTML，每个能独立打开
  • 6. examples/original.html 复制源卡作为参考
  • 7. examples/<second>.html 是完全不同的用户场景，仅用 token 构建
  • 8. ai-prompt.md 含 Cursor rule + 生成模板 + Do/Don't + AI-readable JSON
  • 9. tailwind-tokens.js 通过 node -e "require()" 校验
  • 10. index.html 可视化文档页：sidebar 4 段 + 下载/WorkBuddy 双按钮 + 滚动 active 跟随
  • 11. 本地起 HTTP 服务，所有 17 文件 200，下载 zip 解压可跑
  • 12. main 提交 + gh-pages 同步，线上 6 文件抽样校验 200
